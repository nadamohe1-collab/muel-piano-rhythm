# 뮤엘피아노 리듬게임 🎹⭐

건반을 누르고, 별을 모으는 음악 여행 — 뮤엘피아노 학원 어린이 학생들을 위한
피아노 리듬 학습게임입니다.

---

## 1. 프로젝트 소개

뮤엘피아노 리듬게임은 유치원생·초등학생이 태블릿으로 즐겁게 플레이하면서
박자감, 음이름, 건반 위치, 리듬 패턴, 집중력, 눈-손 협응, 연주 정확도를
자연스럽게 익히도록 만든 웹 기반 게임입니다. 학원 태블릿에서 인터넷 브라우저로
바로 실행할 수 있고, 한 번 접속한 뒤에는 앱처럼 설치해 오프라인에서도 사용할 수
있습니다.

## 2. 뮤엘피아노 브랜드 적용 방식

- 공식 로고 원본(`source-assets/뮤엘피아노_확정.ai`)을 그대로 사용해 SVG/PNG로
  변환했습니다. 로고의 형태, 비율, 색상은 임의로 바꾸지 않았습니다.
- 로고를 분석한 결과 **로고 자체는 검정 단색 워드마크**였습니다. 이를 바탕으로
  로고의 잉크 블랙을 주색(primary)으로 계승하고, 피아노 상아 건반을 연상시키는
  따뜻한 아이보리 배경, "별을 모으는 음악 여행"이라는 부제에 맞춘 골드 강조색,
  피아노 우드톤의 보조색, 아이들이 위축되지 않는 부드러운 코랄(Miss 색상)로
  구성된 디자인 시스템을 새로 설계했습니다. 근거는
  `src/styles/brand.css` 상단 주석에 자세히 적어두었습니다.
- 부팅 화면과 시작 화면에는 공식 로고가 크게, 게임 화면에는 작은 워드마크로만
  표시됩니다.

## 3. 주요 기능

- 이름 입력 → 곡 선택 → 난이도 선택(처음/도전) → (최초 1회) 튜토리얼 → 플레이 → 결과 → 랭킹
- 5개의 자체 제작 연습곡: 도레미 계단, 작은 별 연습곡, 리듬 점프, 나비야, 학교종
- 곡을 클리어하면 자동으로 다음 단계로 이어지며 속도가 0.5배씩 빨라지는 단계 모드 (1배→1.5배→2배→2.5배→3배, 총 5단계). 점수는 단계가 이어지는 동안 계속 누적됩니다
- 3단계부터는 화면에 "실수 게이지"가 나타나며, 놓친 노트(Miss)마다 게이지가 채워집니다. 게이지가 가득 차면 그 시점까지의 누적 점수로 게임이 종료됩니다 (게이지는 매 단계 시작 시 다시 비워집니다)
- 오디오 시간(AudioContext) 기준의 정밀한 리듬 판정 (Perfect/Great/Good/Miss)
- 점수·콤보·정확도·등급(S/A/B/C/다시도전)·별(0~3) 계산
- 곡·난이도별 상위 5명 랭킹 (학생 이름 기준 최고 기록만 반영)
- 교사용 관리 화면 (로고 5초 길게 누르기로 진입) — 랭킹/데이터 초기화
- 오프라인 실행 및 홈 화면 설치 (PWA)
- 학생 이름과 기록은 태블릿(브라우저) 내부에만 저장, 외부 서버 전송 없음

## 4. 기술 구성

- Phaser 4.x (2026년 7월 기준 최신 안정 버전) + TypeScript(strict) + Vite
- Web Audio API로 피아노 음/효과음 직접 합성 (외부 음원 없음)
- IndexedDB로 기록 저장, PWA(Service Worker)로 오프라인 지원
- 외부 CDN 미사용, React/Vue 등 UI 프레임워크 미사용

> **Phaser 4 관련 참고사항**: 이 프로젝트는 2026년 4월 출시된 Phaser 4(WebGL
> 렌더러가 새로 작성된 메이저 버전)를 사용합니다. Phaser 3와 API는 대부분
> 동일하지만, `import Phaser from 'phaser'` 대신 `import * as Phaser from 'phaser'`
> 형태로 가져와야 합니다. 이 프로젝트의 모든 파일은 이미 이 방식으로 작성되어
> 있습니다.

## 5. 설치 방법

1. [Node.js](https://nodejs.org) 20 이상을 설치합니다 (LTS 버전 권장).
2. 이 프로젝트 폴더를 다운로드하거나 `git clone` 합니다.
3. 폴더 안에서 터미널을 열고 아래 명령을 실행합니다.

   ```bash
   npm install
   ```

## 6. 로컬 실행 방법

```bash
npm run dev
```

터미널에 표시되는 주소(예: `http://localhost:5173/muel-piano-rhythm/`)를
브라우저에서 열면 됩니다.

## 7. 빌드 방법

```bash
npm run build
```

`dist` 폴더에 배포 가능한 정적 파일이 생성됩니다. 빌드 결과를 미리 보려면:

```bash
npm run preview
```

## 8. 테스트 방법

```bash
npm run test
```

점수 계산, 판정 경계값, 랭킹 정렬, 이름 유효성 검사, BPM/beat 변환 등
핵심 로직에 대한 자동 테스트가 실행됩니다.

타입 검사만 별도로 실행하려면:

```bash
npm run typecheck
```

## 9. GitHub 저장소 생성 방법

1. GitHub에 로그인 후 새 저장소(Repository)를 만듭니다. (예: `muel-piano-rhythm`)
2. 이 프로젝트 폴더에서 아래 명령을 실행해 코드를 올립니다.

   ```bash
   git init
   git add .
   git commit -m "뮤엘피아노 리듬게임 최초 커밋"
   git branch -M main
   git remote add origin https://github.com/사용자이름/저장소이름.git
   git push -u origin main
   ```

## 10. GitHub Pages 배포 방법

1. GitHub 저장소의 **Settings → Pages** 에서 Source를 **GitHub Actions**로 설정합니다.
2. `main` 브랜치에 push 하면 `.github/workflows/deploy.yml` 워크플로가 자동으로
   빌드·테스트 후 배포합니다.
3. 저장소 이름이 `muel-piano-rhythm`이 아니라면, `vite.config.ts`의 기본
   `base` 값을 저장소 이름에 맞게 바꾸거나, 워크플로가 자동으로 계산하는
   `VITE_BASE_PATH`(저장소 이름 기반)를 그대로 사용하면 됩니다. 사용자 페이지
   (`사용자이름.github.io`)로 배포한다면 `base`를 `/`로 설정하세요.
4. 배포가 끝나면 `https://사용자이름.github.io/저장소이름/` 주소로 접속할 수 있습니다.

## 11. 태블릿 접속 방법

태블릿의 Chrome(Android) 또는 Safari(iPad)에서 배포된 주소를 입력해 접속합니다.
같은 Wi-Fi에서 로컬 개발 서버로 테스트하려면 `npm run dev` 실행 후 터미널에
표시되는 네트워크 주소(예: `http://192.168.x.x:5173/...`)를 태블릿 브라우저에
입력하면 됩니다.

## 12. 홈 화면에 앱 설치하는 방법

- **Android Chrome**: 주소창 오른쪽 메뉴(⋮) → "홈 화면에 추가" 또는 화면 하단에
  나타나는 설치 안내를 탭합니다.
- **iPad Safari**: 공유 버튼(⬆) → "홈 화면에 추가"를 탭합니다.
- **Windows Edge/Chrome**: 주소창 오른쪽의 설치 아이콘을 클릭합니다.

## 13. 오프라인 사용하는 방법

한 번 정상적으로 접속하면 Service Worker가 자동으로 등록되면서, 빌드 시점에
자동 생성된 목록에 따라 게임에 필요한 모든 파일(HTML, JS, CSS, 로고, 아이콘,
매니페스트)을 즉시 내려받아 캐시에 저장합니다. 이후에는 인터넷 연결 없이도
게임 실행, 이름 선택, 곡/난이도 선택, 플레이, 점수 저장, 랭킹 확인, 교사용
데이터 관리까지 모두 오프라인에서 동작합니다.

### 새 버전 업데이트 방식

- 새 버전이 배포되어 있어도 **게임 도중에 강제로 새로고침되지 않습니다.**
- 새 버전이 백그라운드에 준비되면, **시작 화면**에서만 작은 안내 배너
  ("새로운 버전이 준비되었어요.")와 **"업데이트하기"** 버튼이 나타납니다.
- 이 버튼을 눌러야만 새 버전이 적용되고 화면이 새로고침됩니다. 누르지
  않으면 계속 이전 버전으로 정상 작동합니다.
- 학생 이름과 랭킹 기록은 Service Worker의 캐시(파일 저장 공간)와 완전히
  분리된 IndexedDB에 저장되므로, 업데이트 과정에서 절대 삭제되지 않습니다.

### PWA 수동 검증 체크리스트

아래 항목은 실제 태블릿에서만 확인할 수 있어 개발 환경에서는 직접
테스트하지 못했습니다. 배포 후 꼭 확인해 주세요.

**Android Chrome**
1. 사이트 접속
2. 홈 화면에 설치
3. 설치된 앱 실행
4. 곡 1개 플레이 (점수/랭킹 저장까지)
5. 브라우저(앱) 완전 종료
6. 기기 인터넷 연결을 끔 (비행기 모드 등)
7. 앱 재실행
8. 이름/랭킹 기록이 그대로 남아있는지 확인
9. 오프라인 상태에서 게임이 정상 실행되는지 확인

**iPad Safari**
1. Safari로 사이트 접속
2. 공유 버튼 → 홈 화면에 추가
3. 홈 화면 아이콘으로 앱 실행
4. 곡 1개 플레이
5. Safari(앱) 종료
6. 비행기 모드 켬
7. 홈 화면 아이콘으로 앱 재실행
8. 오프라인 상태에서 게임이 정상 실행되는지 확인
9. 두 손가락으로 서로 다른 두 건반을 동시에 눌러 멀티터치가 정상 작동하는지 확인
10. 화면을 두 손가락으로 꼬집거나 길게 눌러도 확대/선택 메뉴가 뜨지 않는지 확인

## 14. 학생 이름과 기록 저장 방식

모든 기록은 **해당 태블릿의 브라우저(IndexedDB)에만** 저장되며, 외부 서버로
전송되지 않습니다. 다른 태블릿이나 브라우저로 이동하면 기록이 보이지 않습니다.

> ⚠️ **중요**: 학생 식별을 이름만으로 처리하기 때문에, 같은 이름을 쓰는 서로
> 다른 학생이 있으면 같은 사람으로 인식되어 기록이 합쳐질 수 있습니다. 이름
> 입력 화면 하단에도 "같은 이름의 친구가 있다면 이름 뒤에 번호를 붙여
> 주세요 (예: 서윤1, 서윤2)"라는 작은 안내가 표시됩니다.
> (예: "민준"이라는 학생이 2명이면 더 높은 기록 하나만 남습니다.)

## 15. 랭킹 초기화 방법

시작 화면 로고를 5초간 길게 눌러 교사용 관리 화면으로 들어간 뒤, 원하는
초기화 버튼(곡별 랭킹 초기화 / 전체 랭킹 초기화 등)을 누르고 확인하면 됩니다.
삭제한 기록은 복구할 수 없으니 신중히 진행해 주세요.

## 16. 공식 로고 교체 방법

향후 로고가 새로 바뀌면 다음 파일들을 교체하세요.

- `public/brand/muel-logo.svg`
- `public/brand/muel-logo.png`
- `public/icons/` 폴더의 아이콘들 (192/512/마스커블 포함)

새 로고가 AI(Illustrator) 파일이라면, PDF 호환 저장 옵션으로 저장된 경우
`pdftocairo -svg 원본.ai 출력.svg`, `pdftoppm -png -r 600 원본.ai 출력` 같은
무료 도구(poppler-utils)로 변환할 수 있습니다.

## 17. 곡 추가 방법

1. `src/game/data/songs/` 폴더에 새 파일(예: `myNewSong.ts`)을 만들고
   기존 곡 파일(`scaleSteps.ts` 등)을 참고해 `SongData` 형태로 작성합니다.
2. `src/game/data/songRegistry.ts`의 `SONG_REGISTRY` 배열에 새 곡을 추가합니다.
3. 저작권 문제가 없는 자체 제작 선율만 사용하세요.

## 18. 노트 데이터 작성 방법

노트는 `{ beat, lane }` 형태로 작성합니다. `beat`는 곡 시작을 0으로 하는
박자 단위 시점이고, `lane`은 0(도)~6(시)입니다. 밀리초를 직접 계산하지 말고
항상 beat 단위로 작성하면, `beatToMs()` 함수가 BPM에 맞춰 자동으로 시간을
계산해 줍니다.

## 19. BPM 변경 방법

각 곡 파일(`src/game/data/songs/*.ts`) 상단의 `const BPM = ...` 값을
바꾸면, 모든 노트 시간이 자동으로 다시 계산됩니다.

## 20. 판정 범위 변경 방법

`src/game/config/constants.ts`의 `JUDGMENT_WINDOWS_MS`(Perfect/Great/Good
기본 판정 범위)와 `BEGINNER_WINDOW_MULTIPLIER`(처음 난이도 확대 배율) 값을
수정하면 됩니다.

## 21. 점수 기준 변경 방법

같은 파일의 `JUDGMENT_SCORE`(판정별 기본 점수), `COMBO_MULTIPLIER_TIERS`
(콤보 배율 구간), `GRADE_THRESHOLDS`(등급 기준), `STAR_RULES`(별 기준)를
수정하면 됩니다.

## 22. 브랜드 색상 변경 방법

`src/styles/brand.css`의 CSS 변수와, Phaser 안에서 사용하는
`src/game/config/theme.ts`의 값을 **함께** 수정해야 화면 전체에 일관되게
반영됩니다.

## 23. 자주 발생하는 오류

- **소리가 안 나요**: 브라우저 자동재생 정책 때문에 반드시 화면을 한 번
  터치/클릭한 뒤에만 소리가 납니다. (시작 화면의 "게임 시작" 버튼을 누르면
  자동으로 초기화됩니다.)
- **기록이 저장되지 않아요**: 시크릿(비공개) 모드이거나 브라우저 저장 공간이
  가득 찬 경우 저장이 실패할 수 있습니다. 일반 모드로 접속하고 저장 공간을
  확인해 주세요. 저장에 실패해도 게임 결과 자체는 정상적으로 화면에 표시되며,
  결과 카드 아래에 "기록을 저장하지 못했어요" 라는 작은 안내 카드가 함께
  표시됩니다.
- **"업데이트하기" 배너가 계속 안 사라져요**: 배너를 누르면 새 버전을 내려받은
  뒤 자동으로 새로고침됩니다. 새로고침 후에도 배너가 남아있다면 인터넷 연결
  상태를 확인해 주세요.
- **GitHub Pages에서 화면이 하얗게 나와요**: `vite.config.ts`의 `base` 경로가
  실제 저장소 이름과 다른 경우 발생합니다. 10번 항목을 참고해 경로를 맞춰주세요.

## 24. 데이터 백업이 없는 구조의 한계

현재 구조는 각 태블릿 브라우저 내부에만 데이터를 저장하므로, **브라우저 데이터를
지우거나 기기를 초기화하면 모든 기록이 사라지며 복구할 수 없습니다.** 여러
태블릿의 기록을 한 곳에서 모아보는 것도 현재 버전에서는 지원하지 않습니다.
정기적으로 중요한 기록은 교사가 별도로 캡처/메모해 두는 것을 권장합니다.

## 25. 저작권 및 라이선스 안내

- 사용한 오픈소스 라이브러리와 라이선스는 `LICENSES.md`를 참고하세요.
- 각 곡 데이터 파일에는 저작권 관련 설명(`copyrightNote`)이 포함되어 있습니다.
- 브랜드 로고는 뮤엘피아노 학원의 공식 자산이며, 이 프로젝트의 오픈소스
  라이선스와 별도로 취급됩니다.

## 26. 향후 온라인 통합 랭킹 확장 방법

현재는 기기별 로컬 저장(IndexedDB)만 지원합니다. 여러 태블릿의 기록을
통합하려면, 무료 티어를 제공하는 백엔드(예: Firebase Firestore 무료 플랜,
Supabase 무료 플랜 등)를 연동해 `src/game/storage/repositories.ts`의
함수들을 "로컬 저장 + 온라인 동기화" 구조로 확장하는 방향을 권장합니다.
이때도 학생 개인정보(이름 외 정보)는 수집하지 않는 원칙을 유지해야 합니다.
